# UCP-1 封筒フォーマット

アプリと LLM の往復に使う最小の JSON 構造。**チャット UI のコピー&ペーストを通過できること**だけを要件とする。

## 要求 (アプリ → LLM)

プロンプト本文に埋め込む。

```json
{
  "ucp": 1,
  "kind": "request",
  "rid": "r_7f3a9c",
  "contract": "trip.itinerary@1",
  "schema": { "type": "object", "properties": { "...": {} } },
  "context": { "destination": "金沢", "nights": 2 }
}
```

## 応答 (LLM → アプリ)

LLM にはこの形で返すよう指示する。

```json
{
  "ucp": 1,
  "kind": "response",
  "rid": "r_7f3a9c",
  "contract": "trip.itinerary@1",
  "data": { "...": "" }
}
```

## フィールド

| フィールド | 必須      | 意味                                                       |
| ---------- | --------- | ---------------------------------------------------------- |
| `ucp`      | ✓         | 封筒バージョン。**探索のセンチネルを兼ねる**ため先頭に置く |
| `kind`     | ✓         | `request` / `response`                                     |
| `contract` | ✓         | `<id>@<version>`                                           |
| `rid`      | 要求のみ✓ | 相関 ID。応答では欠落しうる                                |
| `schema`   | 要求      | LLM への出力仕様 (JSON Schema)                             |
| `context`  | 任意      | アプリ側の現在値                                           |
| `data`     | 応答✓     | 契約に従う本体                                             |

## 探索規則

コードフェンス (` ```json ucp `) は**付けるが、頼らない**。
Claude のコピーボタンや共有シート経由ではフェンスが失われるため、受信側は次の順で探す。

1. フェンス付きブロックの JSON
2. 本文中の `"ucp"` を起点に括弧の対応を取った JSON（**主経路**）
3. `allowBareJson` 有効時のみ、契約に合致する素の JSON

複数の封筒が見つかった場合は `rid` 一致 → `contract` 一致 → 最後に出現したもの、の順で選ぶ。

## 封筒を出す時機

要求側は「その場で出す」か「利用者の承認を待つ」かを指示できる（`buildPrompt` の `emit`）。
封筒の形は変わらず、出させ方だけが変わる。

|               |                                                                     |
| ------------- | ------------------------------------------------------------------- |
| `now`         | 抽出・変換など、やり取りの余地が無い用途。1 ターンで完結する        |
| `on-approval` | 内容を詰めてから確定させる用途。封筒は承認後の 1 ターンだけに現れる |

`on-approval` では封筒が何ターンも後に来るため、要求側は次を満たすこと。

- `rid` を変えずに写すよう明示する（会話が続いても同じ要求だと分かるように）
- 応答待ちの保持期間が対話の長さを跨げること（既定 24h）
- 受信の購読を張り続けること

## バージョニング

- `ucp` は封筒自体の破壊的変更でのみ上げる。
- 契約の変更は `contract` の `@version` で表す。受信側は版が違う封筒を**黙って受け入れない**。
